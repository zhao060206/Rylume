# 保存与重启验收

本次检查覆盖首页误判、手动保存入口、自动保存时序、文字编辑、版本冲突、后台任务阻止重启和更新结果提示。测试使用独立本机数据目录，不使用作者的模型配置或真实图版。

| 场景 | 验收结果 |
| --- | --- |
| 首页点击更新 | 显示“无需保存”，确认后只发起一次重启，不请求不存在的场景保存接口 |
| 顶部保存与原位改字 Ctrl+S | 最新标签写入服务器修订，显示“已保存到本机” |
| 保存途中继续编辑 | 等到第二批修改也写入成功才允许重启；并发保存共用等待任务 |
| 保存服务不可用 | 弹窗持续显示原因、重试和另存操作；不请求重启 |
| 恢复服务后重试 | 最新修改先落盘，再发起重启请求 |
| 409 版本冲突 | 不重试覆盖旧修订；另存独立副本后继续重启，原图保持原修订 |
| 导出任务阻止重启 | 服务端原因直接显示在弹窗，可继续编辑或稍后重试 |
| 1000 px 窗口 | 保存按钮、保存状态和弹窗操作仍可见 |

浏览器验收通过实际点击、输入标签和快捷键执行，随后通过服务器场景与修订号核对保存结果。保存失败、冲突和阻止重启使用测试服务注入，测试服务的重启操作只记事件。正式安装包另行验证下载、替换、启动健康确认与原图保留。

自动回归位于 `tests/test_save_safety.mjs`；UI 使用 `ui/save-state.js` 统一保存状态与队列。`ui/save-ui.js` 的重启弹窗只在保存成功后调用安装接口；错误不会降级为被其他窗口遮挡的短暂提示。
